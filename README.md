# 🎉 פוקינו מסיבה

בינגו‑קלפים לייב למסיבות. המנהל פותח חדר, משתפים לינק/QR, כולם מצטרפים מהטלפון **בלי הרשמה**, מושכים קלפים פיזיים — ומי שמשלים שורה / טור / אלכסון מקבל קונפטי ו‑"זכית! לך תבחר או תגנוב מתנה 🎁".

---

## מה כלול

- **לובי חי** — רואים בזמן אמת מי הצטרף.
- **הצטרפות בלי חשבון** — אורח פותח לינק, כותב שם, בפנים (אימות אנונימי).
- **שעת התחלה + שעת סיום** — המנהל קובע שעות; כולם רואים ספירה לאחור והתראות קופצות: דקה לפני ההתחלה, ובסיום — 5 דקות לפני, דקה לפני, ובהגעה לזמן הסיום.
- **לוח 5×5** אקראי וייחודי לכל שחקן (25 קלפים, 2–A, בלי משבצת חינם — כמו פוקינו קלאסי).
- **סימון חופשי** (אמון מלא) + זיהוי שורה/טור/אלכסון → קונפטי ומודאל זכייה.
- **הזוכה ממשיך את המשחק** — כשמישהו זוכה, המשחק נעצר אצל *כולם*; הזוכה (לא המנהל) לוחץ "בחרתי מתנה — המשך", וזה משחרר את כולם. השאר רואים "X בוחר מתנה…".
- **פיד זוכים חי** + כמה זוכים בסבב.
- **כלי מנהל:** התחלה, סבב חדש (לוחות חדשים), חזרה ללובי.
- **QR לשיתוף** + העתקת לינק.

הכול מובייל‑פירסט ובעברית (RTL).

## הקמה — פעם אחת (בערך 10–15 דק')

### שלב 1 — פרויקט Firebase (חינם)
היכנס ל‑https://console.firebase.google.com → **Add project** → תן שם (למשל `pokeno-party`) → אפשר לדלג על Analytics → **Create**.

### שלב 2 — הפעלת Anonymous Auth
**Build → Authentication → Get started** → לשונית **Sign‑in method** → **Anonymous** → **Enable** → **Save**.

### שלב 3 — Realtime Database
**Build → Realtime Database → Create Database** → בחר אזור (למשל אירופה) → התחל ב‑**Locked mode**.
העתק את כתובת ה‑DB שבראש העמוד (כמו `https://pokeno-party-default-rtdb.europe-west1.firebasedatabase.app`) — תצטרך אותה בשלב 5.

### שלב 4 — חוקי אבטחה
בלשונית **Rules** של ה‑Realtime Database, הדבק והחלף (**Publish**):

```json
{
  "rules": {
    "rooms": {
      "$room": {
        "meta": {
          ".read": "auth != null",
          ".write": "auth != null && (!data.exists() || data.child('adminUid').val() == auth.uid)"
        },
        "players": {
          ".read": "auth != null",
          "$uid": { ".write": "auth != null && $uid == auth.uid" }
        },
        "winners": { ".read": "auth != null", ".write": "auth != null" },
        "live":    { ".read": "auth != null", ".write": "auth != null" }
      }
    }
  }
}
```

> `meta` נשלט רק ע"י המנהל (מי שפתח). `live` פתוח לכל שחקן מחובר — זה מה שמאפשר לזוכה לעצור ולהמשיך את המשחק (לא רק למנהל).
> לבדיקה מהירה בלבד אפשר זמנית: `{ "rules": { ".read": "auth != null", ".write": "auth != null" } }` — ואז לחזור לחוקים שלמעלה.

### שלב 5 — חיבור הקוד ל‑Firebase
1. **⚙️ Project settings → General** → תחת **Your apps** לחץ אייקון **Web** (`</>`) → תן כינוי → **Register app**.
2. העתק את ערכי `firebaseConfig`.
3. פתח את `app.js`, ובחלק המסומן למעלה (`▼▼▼`) הדבק את הערכים:

```js
const firebaseConfig = {
  apiKey: "...",
  authDomain: "pokeno-party.firebaseapp.com",
  databaseURL: "https://pokeno-party-default-rtdb.europe-west1.firebasedatabase.app",
  projectId: "pokeno-party",
  appId: "1:...:web:...",
};
```

> ⚠️ ודא ש‑`databaseURL` הוא הכתובת מהשלב 3. בלעדיה ההתחברות לא תעבוד.

## העלאה לאוויר (פריסה)

צריך להעלות 3 קבצים: `index.html`, `styles.css`, `app.js`. בחר דרך אחת:

### אפשרות א' — Netlify Drop (הכי מהיר)
1. היכנס ל‑https://app.netlify.com/drop
2. גרור את **תיקיית** `pokeno-party` לתוך העמוד → מקבלים לינק מיידי. (התחברות חינם שומרת אותו לקבוע.)

### אפשרות ב' — Vercel
`npm i -g vercel` → בתוך התיקייה: `vercel` ועקוב אחר ההנחיות.

### אפשרות ג' — Firebase Hosting
```bash
npm i -g firebase-tools
firebase login
firebase init hosting      # בחר את הפרויקט, public = התיקייה הזו, SPA = No
firebase deploy
```

> בדיקה מקומית לפני העלאה: אי אפשר לפתוח את `index.html` ישירות מהדיסק. הרץ בתיקייה `python3 -m http.server 8000` ופתח `http://localhost:8000`.

## איך מריצים מסיבה

1. **המנהל** פותח את הלינק → "פתח חדר חדש" → כותב שם → נכנס ללובי.
2. משתפים את ה‑**QR** או מעתיקים לינק לווטסאפ. כל אורח פותח, כותב שם, ומחכה בלובי.
3. (אופציונלי) המנהל קובע **שעת התחלה ו/או סיום** → "שמור שעות".
4. המנהל לוחץ **"התחל משחק"** → לכולם נפתח לוח.
5. מושכים קלפים פיזיים ומכריזים; כל אחד מסמן אצלו.
6. מי שמשלים קו → קונפטי + "זכית!" → **המשחק נעצר אצל כולם**. הזוכה הולך לבחור/לגנוב מתנה, ובסיום לוחץ **"המשך"** → וזה משחרר את כולם. ממשיכים — אפשר עוד זוכים.
7. בשעת הסיום (אם נקבעה) קופצת לכולם התראה. המנהל יכול בכל רגע: **סבב חדש** או **חזרה ללובי**.

## התאמות קלות (בקוד)

- **תבניות זכייה אחרות** (למשל "לוח מלא"/4 פינות): ערוך את `LINES` ב‑`app.js`.
- **צבעים/מיתוג:** משתני הצבע בראש `styles.css` (`--violet`, `--pink`, `--sunny`...).
- **אורך קוד חדר:** הפונקציה `genCode`.
- **זמני התראות סיום** (5 דק'/דקה): בלולאת ה‑`setInterval` ב‑`app.js`.

## מגבלות ידועות (MVP)

- **אמון מלא:** אין אימות שהסימון תואם לקלף שנמשך — מתאים למסיבה, לא לתחרות כספית.
- **מנהל = הדפדפן שפתח את החדר.** ניקוי היסטוריה/מכשיר אחר = איבוד הרשאת מנהל לאותו חדר.
- אם שני שחקנים משלימים קו באותה שנייה בדיוק, שניהם נרשמים בפיד הזוכים, אבל מודאל ה"המשך" יוצג לאחרון שנכתב. נדיר, ולא חוסם את המשחק.
- חדרים לא נמחקים אוטומטית. אפשר למחוק ידנית ב‑Firebase, או פשוט לפתוח חדר חדש בכל אירוע.

רעיונות להמשך: מצב "מנהל מקליד קלפים" עם אימות אמיתי, ניהול מאגר מתנות ומעקב גניבות, וצליל/רטט בזכייה.
